# /review

Strukturierter Review eines Moduls oder Code-Bereichs.

## Verwendung
```
/review skills
/review engine
/review nav
/review kpi-detail
```

## Ablauf

### Schritt 1 – Aktuellen Stand zeigen
- Lies den relevanten Code in index.html
- Zeige die aktuelle Implementierung
- Vergleiche mit Backlog-Items in CLAUDE.md

### Schritt 2 – Analyse
Beantworte diese Fragen:
- Was ist bereits korrekt implementiert?
- Was fehlt noch (aus dem Backlog)?
- Was ist suboptimal aber nicht kritisch?
- Gibt es Bugs oder Risiken?

### Schritt 3 – Priorisierte Liste
```
Sofort nötig:
  1. [Problem] → [Lösung]

Mittelfristig:
  2. [Problem] → [Lösung]

Nice to have:
  3. [Problem] → [Lösung]
```

### Schritt 4 – Empfehlung
Welcher Item sollte als nächstes mit `/implement` angegangen werden?

## Module-Referenz
- **kraft**: Pull-ups, Dips, Weighted Dips, ATG Split, etc.
- **engine**: Lauftypen, Pace, HF-Drift, Kadenz
- **peak**: Intervall-Protokoll, Watt, RPE
- **skills**: Skill Trees, Focus Mode, DNA, Cross-Unlocks
- **struktur**: Dead Hang, Deep Squat, Mobility
- **recovery**: Stress, Muskelkater (nur manuell)
- **nav**: Quick Log Sheet, Profil-Avatar, Recovery Sheet
- **analyse**: Radar-Chart, Streak-Grid, Skill-Unlocks
- **profil**: Badges, PRs, Score-History
